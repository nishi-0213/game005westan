# 自由行動の開始時刻を分散

検証ブランチ `perf/100-pawns` に実装。main・公開版は変更していない。

経路探索を60更新に1度にする対策に加え、自由行動の移動先選択も5秒全体へ分散した。前の実装では最初の60更新に開始が偏り得たが、今回の実装では300更新中の固定担当時刻に実行する。人間・鹿・狼で同じ仕組みを使う。

内部番号idの担当時刻は `id % 60 + 60 * ((id + floor(id / 60)) % 5)`。通常の経路探索の担当回にも一致する。0〜4番は0・61・122・183・244更新目を担当し、仕事から復帰しても変わらない。ポーンの除去で他の時刻を詰め直さない。

自由行動での移動開始から最低5秒待つ条件は維持するため、初回や仕事から復帰した直後は5〜10秒程度待つ場合がある。移動中で担当時刻を逃した場合も次の周期を待つ。静止中なら以降は約5秒間隔。描画FPSに依存せず、シミュレーション時間で進める。

## 確認

- 50体の移動開始が5秒全体に散ること、仕事を挟んだ復帰後も同時にならないこと、開始間隔が5秒未満にならないことを1件の回帰テストで確認した。
- スケジュール・優先順位・仕事性能・鹿の関連30件が成功。TypeScriptチェックとproductionビルドも成功。
- [分散後の負荷分析](分散後の負荷分析.md)で確認した、探索1回の全域計算とGCの重さ自体は今回変更していない。
