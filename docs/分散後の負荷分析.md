# 分散後に残る負荷

対象は検証ブランチ `perf/100-pawns` の分散実装 `4ac4d4c`。この調査ではゲーム処理を変更していない。main・公開版も変更していない。

## 大きいのは探索1回の処理量

100体・自由行動・3倍速でGPU描画を外して測定すると、CPUサンプルの約67.5%が `findPaths`、約14.0%がガベージコレクションだった。`updateRoaming` 配下の処理全体は約72.0%。これらは入れ子を含む割合なので合算しない。

`roaming.ts` は目的地を選ぶ際、まず `findPaths` で全域を調べ、その後で出発点から縦横3マス以内に候補を絞っている。近場を歩くだけでも32×32の全域Dijkstra探索をする。前回の担当更新への分散で開始頻度と集中は抑えたが、1回あたりの探索量は据え置き。

| 自由・3倍速、描画なし | サンプル時間 | 割合 |
| --- | ---: | ---: |
| findPaths（子処理込み、同一関数の再帰は重複集計しない） | 約1,090ms | 67.5% |
| findPaths自身 | 約650ms | 40.2% |
| isBlocked自身（JITによるインライン化を含み得る） | 約328ms | 20.3% |
| ガベージコレクション | 約227ms | 14.0% |
| ポーン占有状態のrefresh（子処理込み） | 約28ms | 1.7% |

全サンプル約1,615ms、測定区間の実行時間約1,570ms。区間前後のProfiler処理を含むため同じ値にはならない。

### 次に効きそうな改善

1. **近場の自由行動で全域探索をしない。** 近場の目的候補に対する探索や、目的が決まった時点で探索を終了する方法を検討する。単に探索範囲を正方形で切ると壁の迂回経路を失うため、到達可能性の扱いを維持する必要がある。
2. **探索中のMap・Set・オブジェクト生成を減らす。** 現在は距離Map、親マスMap、closed Set、探索ノード、到達点ごとの経路getterなどを生成している。再利用する数値配列などに置き換える候補がある。GCが重いことは測定済みだが、割り当て元ごとの比率は今回測っていないので、すべてが探索由来とは断定しない。
3. **通行可否を軽くする。** 探索の隣接マス判定で、壁・家具・植物について文字列キーを作り、Mapを繰り返し参照している。マス番号で参照する通行データを用意する候補がある。建設・破壊・成長・扉の開閉・勢力差の更新漏れを防ぐ設計が必要。

キャッシュは今も16出発点までで、100体では押し出しが起こり得る。ただし今回はヒット率を再測定しておらず、キャッシュ容量を増やすだけの効果はこの調査では判定していない。

## 描画ありでは何が見えたか

同じ100体・自由3倍速を実時間約10秒測定すると、ページのメインスレッドのサンプルは約73.0%がidle、約13.2%がfindPaths、約5.5%がGC、Pixiのrender配下が約2.3%だった。

idleはGPU処理時間を意味しない。別プロセスのGPU処理・ブラウザのフレーム待ちなどは、このページのCPUプロファイルだけでは分離できない。クラウドはSwiftShaderソフトウェアWebGLなので、実機での描画性能や照明・影の負荷は未判定。照明・影を切り替えた比較や実機測定なしに、これらを主因とはしない。

画面の文字や欲求UI更新は今回の未選択状態の測定では上位の主因に現れなかった。選択ウィンドウを多数開いた状態や建造物・たいまつの多いマップの性能を調べた結果ではない。

## 収集指定した場合の補足

100体・収集指定・1倍速の描画なし測定では、findPaths約54.8%、GC約13.5%、占有refresh約3.5%。ただし対象が有限で、測定終了時には61個の環境オブジェクトが収集・寿命で消えている。収集を終えて自由行動になったポーンを含み、純粋に100体全員が採集中の測定ではない。`findWork` の割合は約3.0%だった。

## 計測方法

- productionバンドルを非圧縮・sourcemapありで生成し、関数名を保持した。アプリのソースとルールは変更していない。
- Chromium、1280×720/DPR1、SwiftShader、乱数シード42。各条件1回。CDP CPU Profiler、サンプリング間隔1ms。
- 描画なしは最初の5秒分を進めてウォームアップした後に10秒分を測定。3倍速では15秒分のウォームアップと30秒分の測定に相当する。空腹開始前なので食料探索の影響はない。
- 描画ありは5秒ウォームアップ後、実時間約10秒測定した。約26.15シミュレーション秒進行。GCは測定開始前にも明示実行した。
- 割合は各測定の全サンプル時間に対する値で、描画ありとなしでは分母が異なる。子処理込みの関数と子関数を加算しない。
- 新たな単体テストは追加していない。プロファイラ3条件の完走・JavaScriptエラーなしを確認した。

```sh
npx vite build --base=./ --minify=false --sourcemap
# 別ターミナルでpreviewを4175番に起動
PLAYWRIGHT_MODULE_PATH=/tmp/reconquista-perf/node_modules/playwright node scripts/profile-load.cjs
```

[集計JSON](performance/remaining-load-profiles.json)を保存した。CPUプロファイル本体は `/workspace/scratch/load-*.cpuprofile` に保存している。次の対策はまず自由行動の全域探索を減らすことを推奨する。
