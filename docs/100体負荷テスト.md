# 100体負荷テスト

検証ブランチ: `perf/100-pawns`。比較元: main `9e63040`。
mainとGitHub Pagesは変更していない。このブランチだけ初期ポーンを100体に増やした。中央付近の空きマスに重複せず配置し、全員に既存の初期優先順位を設定する。`?pawns=3`で3体の比較条件に戻せる。最適化の変更は含めない。

## 結果

100体の起動・自由行動・収集は動作し、短時間の6条件ではJavaScriptエラーや死亡はなかった。ただし、100体ではゲーム更新が最大約0.25〜0.34秒かかる場面があり、「重くならない」とは判断できない。

| 条件 | 体数 | FPS | 更新平均 ms | 更新p95 ms | 更新最大 ms | 終了時JSヒープ MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 自由・1倍速 | 3 | 12.38 | 1.64 | 0.9 | 90.1 | 8.99 |
| 自由・1倍速 | 100 | 9.39 | 7.84 | 3.4 | 336.3 | 15.11 |
| 収集・1倍速 | 3 | 12.46 | 0.91 | 2.8 | 34.2 | 7.37 |
| 収集・1倍速 | 100 | 8.88 | 10.82 | 30.3 | 250.8 | 16.05 |
| 自由・3倍速 | 3 | 12.09 | 3.12 | 3.4 | 94.4 | 13.63 |
| 自由・3倍速 | 100 | 10.09 | 17.85 | 12.9 | 342.1 | 16.66 |

p95は更新の95%がその値以下だったことを示す。平均よりp95が小さい条件では、少数の長い処理が平均を押し上げている。収集100体のp95は30.3msで、60FPSの1フレーム分（16.7ms）を超えている。原因箇所を特定するCPUプロファイルは今回取得していない。

## 空腹・睡眠を含む180秒分の比較

同じproductionゲームを固定60更新/秒で180秒分進め、GPU描画だけを外した。自由優先、1倍速。ゲーム内では3.75日分に相当する。通常のブラウザFPS測定とは別の測定である。

| 体数 | 180秒分の処理時間 | 更新平均 ms | 更新p95 ms | 更新最大 ms | 50ms超の更新数 | 終了時JSヒープ MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 3 | 1.08秒 | 0.10 | 0.1 | 69.9 | 1 | 6.66 |
| 100 | 115.72秒 | 10.71 | 5.3 | 342.1 | 497 | 9.45 |

100体はシミュレーション80〜90秒の10秒分だけで105.86秒かかった。この区間は満腹感が20%以下になり始める時期で、90秒時点では86体が空腹だった。空腹時の食料探索などが調査候補となるが、関数別の原因は未特定。更新の約4.6%が50msを超えており、p95だけではこの負荷を捉えられない。

両条件で睡眠と覚醒を確認し、終了時は全員生存、JavaScriptエラーなし。100体は終了時に全員空腹、最低HP約50%だった。食料・植物の量は3体時と同じなので、100体用の食料を追加した比較ではない。また途中と終了時に100体の位置が99種類になる観測があり、密集時の位置重複も別途確認が必要。

短時間の描画あり測定に加え、描画なしでも空腹時に大きく遅延するため、100体で快適に動くとは言えない。今回は計測に留め、AI・経路探索・UIの最適化は変更していない。

## 測定条件と限界

- Chromium、1280×720、DPR 1、productionビルド。クラウドCPUはAMD EPYC 9V45、利用可能CPU数4。
- GPUはSwiftShaderによるソフトウェアWebGL描画。3体でも約12FPSであり、このFPSはAndroidや通常のGPU端末での値ではない。
- 条件ごとに新しいページを開き、乱数シード42、5秒のウォームアップとGC、約10秒の測定を各1回行った。自由は自由優先度1、収集は収集優先度1・全環境オブジェクトを収集指定。収集対象は有限で、常に全員が作業する条件ではない。
- 更新時間はメインticker内のゲーム処理・表示オブジェクト・UI更新を計測し、GPU描画処理は含まない。FPSとlong taskは別途ブラウザから計測した。
- 低FPS時にはシミュレーションが実時間に追いつかない。収集100体は実時間約10.02秒でシミュレーション約8.15秒進行した。
- ヒープ値はGC後のJS領域のみで、GPUメモリやプロセス全体ではない。短時間測定なのでメモリリークの有無は断定できない。
- 生データの `harvested` / `harvestedDuringSample` は消滅済み環境オブジェクト数で、寿命による消滅も含む。純粋な収穫数としては使わない。
- 各1回の測定なので小さな差には環境変動が含まれる。建設、戦闘、大量アイテム、実機タッチ操作は今回の比較対象外。

## 再現方法

このブランチで依存関係をインストールし、production previewを起動する。

```sh
npm ci
npm run build
npm run preview -- --port 4175
```

別ターミナルで、システムのChromiumとPlaywrightを使って実行する。Playwrightはアプリの依存関係に追加していない。

```sh
npm install --prefix /tmp/reconquista-perf playwright
PLAYWRIGHT_MODULE_PATH=/tmp/reconquista-perf/node_modules/playwright node scripts/stress-browser.cjs
PLAYWRIGHT_MODULE_PATH=/tmp/reconquista-perf/node_modules/playwright node scripts/stress-simulation.cjs
```

`?benchmark=1`は計測用APIを有効にし、一時停止で起動する。通常の起動には不要。描画測定スクリプトは `PERF_URL`、`PERF_SAMPLE_MS`、`CHROMIUM_PATH` で接続先・時間・ブラウザを変更できる。追加の単体テストや通常テストへの組み込みは行っていない。

生データ: [描画あり](performance/100-pawns-results.json)、[180秒シミュレーション](performance/100-pawns-simulation.json)。
